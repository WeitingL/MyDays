## Feature Brief

> 由我填寫。

連續型習慣：每天打卡、累積連續天數。兩種面向：

- 養成好習慣（如：連續練習呼吸）
- 戒除壞習慣（如：戒除特定壞習慣連續幾天）

特性：單一內容、每日執行、以「連續天數」為核心價值。

**範圍收窄**：
- 「依星期做不同內容」（如一週運動組合）移到獨立的「一週計劃」feature。
- 「同一習慣多子項目 + 輪替」（如保養）為更後續，兩個 feature 穩定後再處理。

---

## Design Review

> 由 Agent 整理，已明確定案的方向。

- **打卡方式**：單純打勾，每日
- **習慣類型**：好習慣（BUILD）/ 壞習慣（QUIT）
- **好習慣 streak**：連續完成天數
- **壞習慣**：預設成功、只記錄「破戒」；streak = 距上次破戒的天數，自建立日起算
- **統計**：以連續天數為主要指標
- **資料儲存**：Room + Firestore 雙層同步
- **功能入口**：功能 Tab 的 FeatureCard（既有停用入口 `Icons.Default.Loop`）
- **推播提醒**：需要；壞習慣提醒策略獨立（可能預設關閉，避免誘導破戒）
- **視覺風格**：沿用 Liquid Glass，不另設計
- **內容模型**：單一內容，**無 variant、無依星期變化**（那些歸「一週計劃」）

   - 建議：**方案 B**。保留最佳紀錄對習慣養成有正向激勵，欄位成本低。

## Proposed Phases

> 由 Agent 提案，MVP 優先。

### Phase 1 — 核心打卡（MVP）
- 新增 / 編輯 / 刪除習慣（好 / 壞類型）
- 每日打卡（單純打勾）
- Streak 顯示（好習慣連續完成 / 壞習慣距上次破戒）
- 本地 Room 儲存

### Phase 2 — 雲端同步
- Room + Firestore 離線優先同步

### Phase 3 — 提醒通知
- 每個習慣可設提醒；壞習慣提醒策略獨立
